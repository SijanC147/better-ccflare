# better-ccflare

Load balancer proxy for Claude Code. Spreads requests across many account providers → optimal rate limit management.

## CRITICAL: Account & File Safety

**Testing Endpoint**: Automated/scripted testing → use non-Anthropic accounts (ollama, litellm, omniroute, etc.). Real Anthropic accounts get banned for automated usage. The `claude` account is reserved for real Claude Code usage only. Force-route testing via `x-better-ccflare-account-id` header.

**NEVER contact upstream.** No pushes, PRs, issues, comments, bug reports, or any other outbound communication to `tombii/better-ccflare` — or any upstream/third-party repo — unless Sean explicitly says so in that session, and then only after confirming twice. This holds even when we find a genuine upstream bug worth reporting: record it locally (MERGELOG, Linear) and stop. Upstream remotes stay fetch-only (`no_push`). Finding a real defect in upstream code is **not** authorisation to tell them about it.

**Generated files** — tracked, but regenerated by `apps/cli/prepare-workers.ts` during any build. Never hand-edit; review as build output:

## Quick Start

**Build & run**: `bun run build && bun start` (port 8080)

**Quality gate** (run before opening a PR — mirrors CI):
```bash
bun install --frozen-lockfile
bun run typecheck
bun test                              # includes scripts/hextap-contract.test.ts
bun run build:dashboard
bun run scripts/test-hextap-build.ts

```
`bun run lint` (`biome check --write --unsafe`) and `bun run format` **modify files**. Useful, but not a pass/fail gate. Authoritative gate is `.github/workflows/ci.yml`.

**Git safety**:
- `git status` before any changes — track pre-existing uncommitted files
- `main` is **protected**: PR-only, two required checks, zero bypass actors (ruleset `hextap/main`, ID `21627513`). Never push to it, never force-push, never seek admin bypass
- Branch from main: `git switch main && git pull --ff-only origin main && git switch -c feat/name`
- Push the feature branch: `git push -u origin feat/name`
- Repo has both a `main` branch and a `main` tag. **Always use `refs/heads/main`** (not bare `main`) for git log/diff/checkout/merge-base → avoid ambiguous-refspec errors
- Fetch upstream without tags (`git fetch upstream --prune`) — fork and upstream tag names collide
- Commit: `git add <specific-files>` only

**Version** — the **git tag is the version**. Hextap injects it plus the tagged commit as compile-time defines; a release binary reports `better-ccflare 3.8.2 (commit <sha>)`. Hextap does **not** edit `package.json` or `apps/cli/package.json` — they lag the release on purpose. `packages/core/src/version.ts` is not a version-bump target (it holds `CLAUDE_CLI_VERSION`). See `docs/release.md`.

`v*` tags are immutable (ruleset `hextap/release-tags`, ID `21627514`). Fix a failed release forward with a new version, never by re-tagging.

## ⚠️ Database Migrations — Port to PostgreSQL

Every migration added to `packages/database/src/migrations.ts` MUST also be ported to `packages/database/src/migrations-pg.ts`:
1. `ensureSchema()` in `migrations.ts` (SQLite CREATE TABLE)
2. `runMigrations()` in `migrations.ts` (SQLite ALTER TABLE for existing DBs)
3. `ensureSchemaPg()` in `migrations-pg.ts` (PG CREATE TABLE for new installs)
4. `columnsToAdd` array in `runMigrationsPg()` (PG ALTER TABLE for existing DBs)
5. Mirror any SQLite backfill as an `adapter.unsafe(UPDATE ...)` in `runMigrationsPg()`

New tables go in `ensureSchemaPg()` AND `runMigrationsPg()` (`CREATE TABLE IF NOT EXISTS`).
