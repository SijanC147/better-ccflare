# Upstream sync calibration

Repo-specific input for the user-scoped `/sync-upstream` command. That command holds the
generic procedure — phases, conflict rubric, discipline. This file holds everything true
only of better-ccflare, and is authoritative over the command's defaults.

Tracked deliberately: `.claude/` is gitignored here, so a calibration living there would
not survive a fresh clone.

Related: `docs/release.md` (release mechanics), the installed `hextap` skill (toolkit
operation), `/ask-hextap-coordinator` (migration decision history).

## Remotes and refs

| | |
|---|---|
| origin | `SijanC147/better-ccflare` (fork, public) |
| upstream | `tombii/better-ccflare` — **fetch-only**, push URL `no_push` |
| `tombii` | identical read-only mirror of upstream; prefer `upstream` |

**A git tag named `main` exists alongside the branch.** Bare `main` is ambiguous and may
resolve to the tag. Use `refs/heads/main` in every rev-list, merge-base, diff, merge,
checkout, and rebase target.

**Never fetch upstream tags.** The fork publishes its own `v3.x.y` tags whose names
collide with upstream's, pointing at different commits. Use `git fetch upstream --prune`.
For a specific upstream tag, namespace it:
`git fetch upstream "refs/tags/<t>:refs/tags/upstream-<t>"`.

All `gh` commands must pass `--repo SijanC147/better-ccflare` — in a fork, `gh` may
otherwise target tombii's repository.

## Branch protection

`refs/heads/main` is protected by ruleset `hextap/main` (ID `21627513`): **PR-only**, no
direct push, no force-push, no deletion, review threads resolved, **zero bypass actors**.

Required checks, both **strict**:

```
Bun and release tooling
Hextap release contract
```

Strict means a PR whose base moved needs `gh pr update-branch` and a CI re-run before it
can merge. There is no direct-push completion path; a sync must land via PR.

Release tags are protected by `hextap/release-tags` (ID `21627514`): `v*` tags cannot move
or be deleted.

## Commands

Package manager **bun**, lockfile `bun.lock`. Toolchain pinned to **Bun 1.3.14** by
`.hextap.json` and `.github/workflows/ci.yml`.

| Purpose | Command |
|---|---|
| install | `bun install` — then prove `bun install --frozen-lockfile` passes |
| typecheck | `bun run typecheck` |
| test | `bun test` (full suite — it contains `scripts/hextap-contract.test.ts`) |
| lint gate | **`bunx biome check .`** — non-mutating |
| dashboard | `bun run build:dashboard` |
| adapter test | `bun run scripts/test-hextap-build.ts` |
| adapter syntax | `/bin/bash -n scripts/hextap-build` |
| contract | `brew hextap validate --project .` (add `--build` for code changes) |
| build | `bun run build` |

⚠️ `bun run lint` is `biome check --write --unsafe` and `bun run format` is
`biome format --write`. **Both rewrite files** and must never be the pass/fail gate — they
would silently mutate freshly-resolved conflicts. Use them only as a separately-committed
style step.

Note `brew hextap validate --build` regenerates the tracked inline workers; re-check the
tree afterwards.

## Generated but tracked

Regenerated by `apps/cli/prepare-workers.ts` during any build:

```
packages/database/src/inline-vacuum-worker.ts
packages/database/src/inline-incremental-vacuum-worker.ts
packages/database/src/inline-integrity-check-worker.ts
```

These **must stay tracked and un-ignored**, even though upstream gitignores them. Two
reasons: the release quality phase runs `typecheck`/`test` *before* the adapter
regenerates them, so an absent file fails on missing imports; and ignored-and-untracked
would let a release ship generated code absent from the tag's tracked tree, because the
clean-tree gate uses `--untracked-files=no`.

Regenerate at pinned Bun and review the diff. A diff here when no worker *source* changed
is a signal — usually the wrong Bun version — not churn to stage away.

`packages/dashboard-web/dist/**` is generated and gitignored — ignore it.

`packages/proxy/src/inline-worker.ts` is tracked but **orphaned**: nothing imports it since
the UsageCollector migration and no build regenerates it. Not a live protected file;
upstream's ignore/delete treatment may be accepted. Do not conflate it with the three
above.

## Inviolable — Hextap release machinery

Upstream has never heard of Hextap (`git grep -il hextap upstream/main` returns nothing),
so these should never conflict. If one does, **stop and investigate** rather than resolve.

```
.hextap.json                        scripts/hextap-build
.hextap/tap-registration.json       scripts/hextap-contract.test.ts
.hextap/SETUP.md                    scripts/test-hextap-build.ts
.hextap/rulesets/main.json          .github/workflows/hextap-release.yml
.hextap/rulesets/release-tags.json  .github/workflows/ci.yml
apps/cli/hextap-build.ts            apps/cli/hextap-targets.ts
packages/core/src/build-identity.ts
```

`.hextap.json` and `.hextap/tap-registration.json` must stay **byte-identical** to each
other and to the tap's `Projects/better-ccflare.json`. That equality is a release and
recovery boundary — changing it can permanently close `homebrew-only` recovery for
existing tags. **A sync must never touch it.**

Verify after merging:

```sh
git diff --stat "refs/heads/main"...HEAD -- .hextap.json .hextap/ scripts/hextap-* \
  .github/workflows/hextap-release.yml .github/workflows/ci.yml \
  apps/cli/hextap-*.ts packages/core/src/build-identity.ts
shasum -a 256 .hextap.json .hextap/tap-registration.json   # must match
```

## Fork-owned features

Preserve across any sync; if upstream refactors a file these touch, replay the fork diff
onto upstream's version rather than dropping it:

- **Project attribution** — `X-CCFlare-Project` header, `project_id` DB column, worktree
  path attribution, dashboard project filters and grouped request stream. Spans
  `usage-collector.ts`, `request.repository.ts`, `migrations.ts`, `migrations-pg.ts`,
  `types/src/{request,api}.ts`, `proxy.ts`, and several dashboard components.
- **Dashboard customizations** — color-coded model and account chips, collapsible sidebar
  with localStorage persistence, 24-hour time toggle.
- `apps/cli/README.md` — keep ours untouched.
- Root `README.md`, `CLAUDE.md`, `docs/**`, `.claude/**` — fork-customized. Content inside
  `<!-- fork:keep -->` … `<!-- /fork:keep -->` is inviolable.

Any migration added to `packages/database/src/migrations.ts` must also be ported to
`migrations-pg.ts` — see `CLAUDE.md`.

## CI workflows

The fork disables upstream workflows by renaming them `*.yml.disabled` (GitHub only loads
`*.yml`/`*.yaml`) and owns two live files: `ci.yml` and `hextap-release.yml`. Upstream has
~10 live workflows against the fork's 3, so upstream workflow changes routinely arrive as
either a new live file or a modify-against-a-renamed-`.disabled` file. Each needs a
deliberate call. Keep ours by default; record any adoption as a follow-up.

| Conflict | Resolution |
|---|---|

| `.github/workflows/release.yml` | Fork deleted it; upstream still develops it, so git reports **delete/modify** and "keep the file" is wrong. `git rm`. `scripts/hextap-contract.test.ts` asserts it does not exist and that exactly one workflow owns the `v*` trigger; restoring it creates two publishers racing the same tag. **Overrides rubric rule 1.** |
| `packages/dashboard-web/src/lib/version.ts` | Keep the fork shape: **root** `package.json` fallback, both `__BETTER_CCFLARE_VERSION__` and `__BETTER_CCFLARE_COMMIT__` declares, `displayVersion()`, and the `version`/`commit` exports — `navigation.tsx` imports both. Add `getVersion()` only as an *additive* alias. |
| `packages/dashboard-web/build.ts` | Must read `BETTER_CCFLARE_BUILD_VERSION` / `BETTER_CCFLARE_BUILD_COMMIT` and inject both defines. Upstream's version ignores those env vars and reads `apps/cli/package.json`, so a `v3.8.2` release would embed `3.8.1` and fail `test-hextap-build.ts` with "dashboard did not embed the release version and commit". |
| `CCFLARE_BUILD_SUFFIX` (upstream) | Yields `X.Y.Z+suffix`; Hextap **rejects SemVer build metadata**, so it can never be part of release identity. Non-Hextap builds only; fail closed if combined with Hextap identity. |

Accepted loss: upstream's release workflow credits contributors in release notes via
`gh pr view`. Hextap publishes with `gh release create --generate-notes` and exposes no
custom-body hook, so that logic is not preserved. Recover via a **`.github/release.yml`**
notes-configuration file — that is *not* `.github/workflows/release.yml` — or a future
toolkit hook. Never by restoring a second publisher.

For a Hextap-touching conflict not covered here, escalate via `/ask-hextap-coordinator`
rather than guessing. These files carry boundaries where a plausible-looking resolution
can silently break an immutable release or close recovery.

## Breaks without producing a conflict

Conflict count is not coverage. Audit every item after resolving:

1. **A second release publisher.** Grep every `.github/workflows/*.yml{,aml}` for a `v*`
   tag trigger, `gh release create`/`upload`, `--clobber`, release deletion, Formula
   writes, or tap pushes. The contract test matches a literal trigger shape and can be
   evaded by equivalent YAML written differently.
2. **New workspace package.** Must appear in root `workspaces` *and* a regenerated
   `bun.lock`, or `bun install --frozen-lockfile` fails the release. This killed the first
   `v3.8.0` tag.
3. **Bun version bump** beyond pinned `1.3.14` — a manifest + tap recovery-boundary
   change, not a CI tweak. Never change one side silently.
4. **Build scripts and compile flags** — renamed scripts, changed output paths, new
   network-requiring pre/post-install steps (the release build runs **offline**), or a
   removed `--no-compile-autoload-*` flag in `apps/cli/build-standalone.ts`.
5. **`apps/cli/src/main.ts` informational flags.** `--version`/`-v` must print
   `better-ccflare X.Y.Z[-pre] (commit FULL_SHA)` via `getBuildIdentitySync()`, exit 0,
   write nothing to stderr, resolve *before* config/database/server init, and not treat a
   `-v`/`-h` already consumed as another option's value as informational.
6. **Build-identity exports** — `normalizeBuildVersion`, `normalizeBuildCommit`,
   `formatBuildIdentity`, `getBuildIdentitySync`, `getCommitSync`, and both compile
   defines, across `build-identity.ts`, `version.ts`, `core/src/index.ts`.
7. **Release asset names** — duplicated across `.hextap.json`, the tap registration,
   `hextap-targets.ts`, tests, and the Formula template. A rename is a coordinated
   source/tap change, never a local edit.
8. **Bare invocation.** The Homebrew service runs `better-ccflare` with **no arguments**
   and relies on that starting the server. A changed default breaks the service even with
   green build CI.
9. **Dashboard output path** — the compiled server expects
   `@better-ccflare/dashboard-web/dist/embedded`; a layout change can compile and still
   not serve.
10. **Required check names** — renaming needs `.hextap/rulesets/main.json`, live ruleset
    `21627513`, the contract test, and online-doctor expectations updated together.
11. **App defaults the Formula documents** — database path, `.env` loading,
    `BETTER_CCFLARE_LOG_DIR`, default port 8080. Changes make the tap's caveats and
    service block stale with no conflict in either repo.

## Sync ledger

`MERGELOG.md`, newest first, with the anchor marker:

```
<!-- last-sync-sha: 412e63266475dd5b8ec485a8d8f5778586172bfd -->
```

That is the **upstream tip consumed**, not the fork-side merge commit — conflating the two
silently re-syncs or skips a range. Do not hand-edit it.

## Bucketing

Monorepo: `packages/` aggregates ~20 workspaces. Bucket at workspace granularity — each
`apps/<app>` and `packages/<pkg>` is its own bucket. Group root-level files
(`package.json`, `README.md`, `CLAUDE.md`, `Dockerfile`, `.gitignore`, `tsconfig.json`,
`biome.json`) into one `root-config` bucket, and `.github/`, `docs/`, `scripts/` each as
their own.
